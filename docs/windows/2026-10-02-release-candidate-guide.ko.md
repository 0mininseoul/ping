# Ping Windows 0.4.2 설치 후보

최신 후보는 [0.4.3 설치 안내](2026-10-03-windows-0.4.3-candidate.ko.md)를 따른다. 아래는 이전 0.4.2 검증 기록이다.

생성된 설치 파일: `windows/dist/PingSetup-v0.4.2.exe` (약 204 MiB).
지원 환경은 Windows 11 24H2 이상(build 26100+), x64 또는 ARM64다.

**디자인 교정 후보:** 0.4.2에는 현재 Mac 소스를 기준으로 바꾼 대화창과 룸 관리 UI가 들어 있다. [교정 범위와 화면 확인](2026-10-03-mac-design-correction.ko.md)을 참고한다. 0.4.0/0.4.1 EXE에는 이 수정이 없다. 설정·온보딩·거울·리뷰의 전체 디자인 일치 확인은 남아 있다.

**실기 검증 진행 중:** 초기 EXE의 PowerShell 오류는 0.4.1에서 수정했고, 그 EXE는 실행 중인 Ping 때문에 `0x80073D02`로 안전하게 중단하는 것까지 확인했다. 0.4.2는 서명·내용·읽기 전용 오프라인 payload 검사를 마쳤으며 실제 성공 설치·제거·재설치는 아직 수행하지 않았다. 기존 0.4.0 앱은 계속 실행 중이다. 정상 종료 후 계정·설정 보존을 확인하며 진행한다.

[GitHub CI 성공](https://github.com/0mininseoul/ping/actions/runs/37032773315), 소스 `e09d7af`. 원래 인증서로 서명한 x64/ARM64 앱과 Microsoft 런타임을 EXE에 포함한다. 인터넷 연결 없이 패키지를 설치할 수 있으며, 메시지 서비스에는 인터넷이 필요하다. 아직 공개 릴리즈/웹 다운로드를 교체하지 않았다.

## 설치

1. 기존 Ping이 실행 중이면 트레이에서 종료한다.
2. EXE를 **일반 실행**한다. 전체 설치를 관리자 권한으로 실행하지 않는다.
3. 최초 인증서 신뢰가 필요할 때만 UAC를 승인한다. 외부 EXE 자체는 공인 코드 서명이 없어 SmartScreen이 경고할 수 있다. 앱 MSIX의 서명과 기존 Ping 인증서 일치는 확인했다.
4. 바로가기/설치 후 실행 여부를 선택한다. 시작 프로그램은 앱 설정에서 선택한다.
5. 정보 탭에서 Windows 버전 `0.4.2.0`을 확인한다. 별도로 .NET을 설치하거나 Supabase 설정을 입력할 필요가 없다.

계정과 설정은 유지한다. 설치 관리자를 통한 제거는 현재 사용자의 최신 계정·설정을 먼저 보존하고, 재설치는 기존 계정을 덮어쓰지 않는다. 익명 계정의 로컬 제거는 앱 설정에서 별도 확인한다. 직접 저장한 영상과 서버 계정/룸은 제거 프로그램이 삭제하지 않는다.

## 실제 기기에서 남은 확인

자동 검사와 실제 사용을 구분한다. 아래 결과는 아직 얻지 않았다.

- 비관리자 설치, 오프라인 패키지 설치, 인증서 승인/취소, 실패 재시도/취소. 트레이 종료 후 제거·재설치에서 같은 계정·룸·설정 복구. 업데이트에서 계정 보존.
- 카메라·마이크 선택, 권한 거부/재승인, 연결 해제, 얼굴 거울 `Alt+P`, 화면+얼굴 `Alt+L`, 3초 녹화→리뷰→승인/취소. 녹화·재생·빠른 전송·자동 회신에서 소리와 위치 확인.
- 별도 테스트 계정/룸의 Mac↔Windows 영상·채팅·이미지·답장·반응·초대·삭제·알림·자동 회신. 기존 사람/룸을 임의로 테스트 대상으로 사용하지 않는다.
- 실제 여러 모니터/다른 DPI, ARM64 PC 실행, iPhone/Watch QR 연결과 갱신 토큰 공유.

2026-10-03 현재 DISPLAY3(세로 모니터)에서 진단용 메신저·설정·거울·재생 검사 167개를 통과했다. `windows/scripts/test-ui-smoke.ps1 -MonitorDeviceName '\\.\DISPLAY3'`로 다음 시험 창도 해당 모니터에서 생성한다. 이 지정은 진단 빌드에만 적용된다. 실제 화면 캡처 사전 확인은 앱과 같은 PerMonitorV2 DPI에서 code0이며, 실제 3초 화면+얼굴 녹화는 카메라 없음(code4)으로 중단됐다. 사용자가 현재 카메라가 없다고 확인했으므로 카메라·마이크 실기 검증은 여전히 남아 있다.

실기 확인에서 나온 중요한 결함부터 고친다. 새 합성 검사만 계속 늘려 제품 완료로 간주하지 않는다.

## 산출물 확인

- EXE: `213875782` bytes. SHA-256: `E6310761307165CDF647714FE2319B36B7F74A388DAC85ABF0CCFC373253EFE4`.
- 두 MSIX: `0.4.2.0`, 원래 identity/Publisher, OS 서명 `Valid`, 인증서 `12D9D5539B1851EE1A0725CCFCB6A9CCD098DCDC`.
- 네이티브 DLL CPU: x64 `0x8664`, ARM64 `0xaa64`. 자체 포함 .NET, 공개 pinned 프로젝트 구성, 업데이트 helper 포함. 개인키/사용자 세션/진단 코드용 의존성은 포함하지 않는다.
- Core 271/App 309, WinUI 175 및 오프라인 payload 4개/데이터 보존 5개 검사 통과. 실제 배포 DLL에 새 MessageBubble 타입이 있고 진단 타입은 0개임을 확인했다. 실제 EXE는 Inno compiler가 성공적으로 생성했다.

서명된 앱 두 개와 Microsoft 런타임으로 fallback `windows/dist/Ping-Windows-v0.4.2-sideload.zip`도 생성했다. 두 아키텍처의 OS PowerShell 5.1 읽기 전용 설치 payload 검증을 통과했다. SHA-256은 `C162E415D067979EBEC5D849BFA74A239C3C4A0C927ECEDEE04090C91D0560D6`이다.
