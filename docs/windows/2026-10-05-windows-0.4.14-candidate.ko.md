# Ping Windows0.4.14 설치 후보

소스는 `cde5133432f0ccf63d056ee0d4bd56e201f16401`이다. [CI37270892324](https://github.com/0mininseoul/ping/actions/runs/37270892324)는 Core285/App348, Windows PowerShell5.1 계정 보존12개와 오프라인 설치 payload4개를 통과했다. x64·ARM64 정상 패키지 빌드는 경고0/오류0이고 EXE까지 생성됐다. 공개 다운로드 채널은0.3.46이다.

이번 수정은 [알림 활성화 등록 순서와 인자 해석](2026-10-05-windows-notification-startup.ko.md)에 관한 것이다. 등록 전 활성화 인자를 읽던 실제 네이티브 비정상 종료와 SDK 사전이 Ping의 쿼리 형식을 잘못 읽는 문제를 재현하고 수정했다. UI와 계정을 열지 않는 실제 네이티브 검사에서 첫 알림 처리4개, 두 프로세스 전달2개, 시작 큐 전달4개가 통과했다. 격리 COM 진단의 통과를 설치본의 실제 OS 클릭 성공으로 표시하지 않는다.

Mac 소스 기반 대화창·설정·첫 사용 안내와 Pretendard Variable/OFL,14/21 본문·12/18 보조 타이포그래피, 사진 입력/확대와 원형 얼굴 재생, 룸 관리, 창 배치 복원을 포함한다. UI 소스는0.4.12 이후 바꾸지 않았으므로 이전 실제 WinUI313개를 새 후보에서 다시 실행했다고 표시하지 않는다. 패키지에서 기능 타입·폰트 원본 해시와 라이선스를 확인했고 진단 타입과 개인 계정 파일은 포함되지 않았다. 근거: `windows/artifacts/ci-37270892324/package-verification.json`.

## 실제 설치 검증

실제 EXE로0.4.13→0.4.14 업데이트가 exit0으로 완료됐다. 현재 설치는0.4.14.0 / Status Ok다. 앱을 실행하지 않은 상태에서 일반 저장소 네 파일과 패키지 런타임 저장소 세 파일의 해시·길이가 이전과 같고, 세션/백업은 최초 계정 보존 기준과 일치함을 확인했다. DISPLAY3 배치 값도 그대로다. 설치된 App·Core·native DLL·Pretendard·OFL은 검증 MSIX와 같으며 계정 보존/제거 스크립트는 줄바꿈 정규화 후 소스와 같다. 시작 메뉴와 제거 프로그램 등록도 확인했다. 근거: `windows/artifacts/install-0414-3584e04ccc8842b8a385bd88235856d9`의 `upgrade-process.json`, `upgrade-verification.json`.

이번 후보에서 제거·재설치나 실제 열린 창 위치 검사를 다시 실행한 것은 아니다. 앞선0.4.13 제거·재설치 성공과 계정 보존 결과는 [이전 후보](2026-10-05-windows-0.4.13-candidate.ko.md)를 따른다. 설치 스크립트는 이번 알림 수정에서 바꾸지 않았다.

후속 [설치 거부·재시도 검사](2026-10-05-windows-deployment-retry.ko.md)에서는 이전0.4.13 EXE의 실제 `Add-AppxPackage`가 `0x80073D06`으로 거부되고 EXE가 exit3으로 종료됐다. 기존0.4.14와 계정 파일7개, 설치 파일·등록이 유지됐으며0.4.14 EXE 재실행은 exit0으로 완료됐다. 설치 UI의 Retry 클릭과 MSIX staging 도중 rollback은 이 결과에 포함하지 않는다.

설치본의 실제 OS 알림 클릭·종료 상태 브로커 실행, 카메라/마이크 촬영, Mac 상대 송수신, ARM64 실제 기기, 혼합 DPI·고대비 및 설치 중간 실패 복구 검증은 남아 있다. 전체 제품 목표의 완료를 뜻하지 않는다.

전체 사용자 요구사항과 구현·실기 근거는 [완성 조건 대조](2026-10-05-windows-completion-audit.ko.md)를 따른다. 앱을 완전히 종료한 후 도착한 신규 메시지의 WNS 원격 배너는 별도 미구현 항목이며 Azure/Entra 앱 등록·PFN 매핑과 서버 연결이 필요하다. 앞선 알림 등록 순서 수정이나 기존 배너 cold activation 검증으로 이 기능을 완료 처리하지 않는다.
