# 채팅 표시와 이메일 방식 철회

## 제품 요구

가입 절차 없이 닉네임으로 바로 시작하면서 노트북과 데스크톱에서 같은 친구·룸·메시지를 이어 사용한다. 사용자가 이메일 방식을 폐기해도 된다고 명시하여 이메일 인증 UI/API/운영 설정 스크립트를 제거했다. 운영 Auth/SMTP 설정은 적용한 적이 없으며 기존 계정·룸·메시지와 세션 파일은 변경하지 않았다.

권장안은 기존 기기에서 새 PC의 일회성 연결 요청을 승인하고 이후 자동 연결하는 흐름이다. 공개 이름#번호는 연락용 ID로만 사용한다. 기기별 인증 세션은 독립적으로 유지하고 같은 Ping 계정에 권한을 부여하는 연결·해제 로직이 필요하다. 기존 Supabase/Vercel을 유지할 수 있으나 기기 연결과 권한 처리를 추가하는 설계/구현은 아직 남아 있다. 기존 QR의 refresh-token 복사는 이 요구를 충족하지 않는다. 모든 연결 기기를 잃었을 때를 위한 선택형 복구 키도 제안 단계다.

## 채팅 변경

- 닉네임 옆에 로컬 시간 HH:mm을 항상 표시하고 시간 툴팁을 제거했다. 1:1 및 본인 메시지도 동일하다.
- 메시지 행의 기본 밝은 hover/pressed 배경을 투명하게 하고 선택은 둥근 옅은 강조색으로 표시한다. 재배치 애니메이션은 끈다.
- polling마다 영상/채팅/룸/타임라인 컬렉션을 Clear하고 모든 행을 재생성하던 경로를 증분 동기화로 바꿨다. 같은 메시지의 행과 로드된 사진·링크 프리뷰, 인라인 영상 상태를 유지한다. 영상 seen 상태와 반응은 기존 행에 반영한다.
- 타임라인을 적용하기 직전에 현재 화면 위치를 기록한다. 하단 근처에서 읽는 중이면 새 메시지를 따라가고, 이전 대화를 읽는 중이면 보이는 메시지와 그 위치를 기준으로 복원한다. 네트워크 요청 동안 사용자가 이동한 스크롤을 이전 위치로 되돌리지 않는다.
- 일반 새로고침은 선택된 메시지로 스크롤하지 않는다. 알림의 특정 메시지 열기, 방 최초 진입, 본인 메시지 전송은 명시적으로 해당 위치를 표시한다.
- '삭제' 계정 버튼을 '이 PC에서 제거'로 바꾸고 서버 계정과 방 참여가 유지된다는 설명을 추가했다.

## toma1 삭제 요청

Supabase 연결 도구에서 고정 Ping 프로젝트 `qxjtprxvjmaxlbtljcjw` 조회가 권한 거부로 실패했다. 정확한 계정 UID, 운영 DB 상태, 소유한 방을 확인하지 못했고 서버 계정·로컬 계정·룸을 삭제하지 않았다.

저장된 마이그레이션 기준으로 Auth 사용자 삭제는 profiles 및 room_members에 cascade되어 참여한 방에서 빠진다. rooms.owner_uid도 cascade이므로 해당 사용자가 방장인 방은 방 자체와 다른 멤버의 방 참여/방 메시지까지 삭제될 수 있다. 안전한 계정 삭제를 위해서는 정확한 UID를 확인하고 소유한 공동 방의 방장 이전, 방 나가기, Storage와 Auth 세션 처리 순서를 정해야 한다. 이 PC의 로컬 저장 계정 제거는 서버 삭제/방 나가기와 다르다.

## 산출물과 검증 상태

Windows 버전 0.4.18.0. 이전 작업표시줄 아이콘 변경을 포함한다. 요청된 EXE 생성을 위한 build-only 패키징 범위만 수행하며 자동 테스트·검증 빌드·앱 실행·화면 확인·별도 리뷰는 수행하지 않는다. 채팅의 실제 표시/스크롤과 여러 PC 송수신은 미검증이다.

- 소스 커밋 `9ddbf80`, `codex/windows-parity`에 push 완료.
- [설치물 생성 37296259861](https://github.com/0mininseoul/ping/actions/runs/37296259861): build_only=true, 6m33s에 패키징 성공. 테스트 restore/실행은 skipped. 릴리즈와 웹 다운로드 게시는 하지 않았다.
- EXE 다운로드 완료: `windows/dist/PingSetup-v0.4.18.exe`. 자동 설치/실행은 하지 않았다.
