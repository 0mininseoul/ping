# Windows 통합 메신저 화면 검증

2026-09-30, `codex/windows-parity`. 최신 Mac의 방 목록·대화 타임라인·입력창 구조를 기존 WinUI 앱의 실제 주 창에 적용했다. 시작/트레이/히스토리 활성화는 같은 창을 사용한다. 이 문서는 전체 Windows 완성판의 완료 보고가 아니다.

## 확인한 결과

- Core 89개, App 253개: Release 자동 테스트 통과.
- 별도 진단 빌드에서 실제 WinUI 창과 바인딩·메뉴·버튼을 실행하는 28개 항목 통과. 메모리 내 가짜 RPC/Storage를 사용하며 운영 계정, 서버, 카메라, 트레이, 시작프로그램을 사용하지 않는다.
- 방 전환, 빈 방 안내, 방별 초안 복원, 답장 대상 식별, 실제 전송 버튼 클릭과 입력창 정리, 오프라인 배너, 설정 창 열기/닫기, 일반 닫기 후 동일 HWND 재열기, 최소 760×540 크기의 입력창을 확인했다.
- 실제 렌더링에서 밝은/어두운 테마, 오프라인, 설정, 최소 크기 화면을 확인했다. 현재 모니터 배율의 검사이며 다른 모니터나 모든 DPI 조합을 확인한 것은 아니다.
- 렌더링 검증으로 방 인원 바인딩 실패, 설정 창의 기본 WinUI 리소스 누락, 프로그램식 닫기의 종료 경로, 초기 중복 로드가 최신 메시지 스크롤을 초기화하는 문제를 발견하고 회귀 검증 후 수정했다.
- 독립 리뷰 후 자동 새로고침 전체를 UI 스레드로 옮기고, 숨김에서 복귀하면 새 snapshot을 표시한 다음 읽음 처리하도록 수정했다. 실제 타이머 호출과 새 메시지 표시 후 읽음 RPC 순서를 fixture에서 확인했다. 기본 전송 방은 연결·송신·설정 변경 후 갱신하며, 타임라인 새로고침은 읽던 위치를 보존하고 전송 뒤 최신 메시지를 표시한다.
- x64 Release 및 서명 없는 검증 MSIX: 경고 0개/오류 0개. 정상 Release DLL에서 진단 runner가 제외됨을 확인했다. 최종 검증 패키지: `windows/artifacts/local-x64-e58e92cf4fa84f1f8e21817718ebef91/Ping.Windows.App_0.3.46.0_x64_Test/`.

재현 명령:

```powershell
./windows/scripts/test-ui-smoke.ps1
./windows/scripts/build-local.ps1 -Configuration Release -Package
```

진단 실행 결과는 `windows/artifacts/ui-shell-<GUID>/result.json`, `phases.txt`, PNG에 저장된다. 진단 실행 파일은 필수 인자를 생략하면 종료하며 실제 계정 시작 경로로 넘어가지 않는다. 정상 빌드에서는 진단 코드가 제외된다. 테스트 스크립트는 종료 코드만 믿지 않고 `Success` 결과를 확인한다.

확인한 화면: `windows/artifacts/ui-shell-27b9b8d29f2b40d5b6239d3728673dd2/`. 빌드 로그와 실패 재현 결과는 이 계획의 gitignored `.superpowers/sdd/2026-09-30-windows-messenger-shell/`에 보존한다.

## 남아 있는 전체 제품 작업

실시간 수신/자동 floating 재생과 출처별 catch-up 정책, 영상 썸네일·원형 얼굴 및 재생 크기, 자동 회신과 카메라 ownership, 전체 설정·계정/기기 연결, 오프라인 EXE 설치/업데이트 검증을 이어서 구현해야 한다. 물리 카메라, 실제 한국어 IME 키 입력, 고대비 시스템 설정, 모든 DPI/다중 모니터, Mac과 교차 송수신은 아직 확인하지 않았다. 설정 창은 기존 내용의 실행 가능성을 확인한 상태이며 최신 Mac 설정 기능 전체와 디자인 이식은 후속 범위다.

검증 MSIX는 서명 없는 로컬 산출물이며 공개 설치 프로그램이 아니다. 로컬 backend 구성과 릴리스 서명 키가 없는 상태에서 실제 서비스 설치/교차 송수신까지 성공했다고 주장하지 않는다.
