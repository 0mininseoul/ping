# Windows 네이티브 UI와 실제 서버 QA

이전 서비스 검증에서 만든 A/B 소유 익명 계정을 복구해 실제 Windows 대화창과 Ping 서버를 함께 검사했다. 새로운 계정은 만들지 않았다. 명시적인 진단 옵션 `--ui-owned-live`와 `PING_UI_SMOKE` 빌드에서만 실행되며 일반 앱 실행·일반 fixture 검증은 원격 QA를 시작하지 않는다. 현재 Ping 프로젝트 호스트를 확인하고, A/B의 기존 룸 목록이 모두 비어 있을 때만 고유 QA 룸을 생성한다.

DISPLAY3에서 25개 검증이 통과했다. 원본 결과는 `windows/artifacts/owned-native-965ee2583ab94948821b433821ceb508/`다.

- 복구된 계정 식별자·초대 후 두 멤버·양쪽 실제 대화창의 룸 로딩을 확인했다.
- 작성창 바인딩과 네이티브 전송 버튼을 통해 한글·이모지·여러 줄 텍스트를 보냈다. TextBox의 CR과 LF 표현 차이는 비교에서 정규화한다. 실제 IME 타이핑 검증을 뜻하지 않는다.
- 수신 본문에 웹·메일 링크가 개별 WinUI Hyperlink로 나타났다. 답장·인용과 리액션이 반대쪽 타임라인에 도착했다. 방향과 1:1 이름 숨김은 행 모델을 검사했으며 링크는 실제 시각 트리를 검사했다.
- 사진 입력 reader·전송 버튼·비공개 업로드·수신 다운로드와 네이티브 디코딩을 함께 확인했다. 원본 사진 SHA-256이 다운로드와 같고 960×640 메타데이터가 전달됐다.
- 소유한 합성 3초 얼굴 모드 MP4를 보내 수신 UI의 원형 인라인 플레이어로 재생했다. 네이티브 디코더의 크기와 종료 후 서버 `seen` 반영을 확인했다. 카메라·마이크 녹화를 의미하지 않는다. RenderTargetBitmap은 MediaPlayerElement 영상 픽셀을 담지 않으므로 렌더의 빈 영상 부분은 레이아웃 확인용이다.
- 메시지·미디어 삭제와 양쪽 룸 나가기를 수행해 룸 목록이 다시 비었음을 확인했다. 결과의 cleanup 단계에 오류가 없었다. 기존 사용자 세션과 백업 두 파일은 해시·길이가 같다. 별도 설정 파일은 없었다.

## 제품 수정

실제 QA에서 Windows StorageService가 사진 너비·높이를 null로 반환하는 문제를 발견했다. 새 네이티브 `ChatMediaStorageService`는 업로드 전에 Windows BitmapDecoder의 방향을 반영한 크기를 읽고 기존 64 MP 제한을 적용한다. 저장소 업로드·다운로드·삭제는 기존 구현에 위임한다. AppCoordinator와 실제 UI QA가 같은 adapter를 사용해 전송 payload에 크기를 포함한다. Mac·SQL·저장소 정책은 바꾸지 않았다.

## 실패 기록과 검증 범위

첫 실행은 메시지 입력 전 진단 프로세스가 종료됐다. 기록된 소유 룸이 비었고 멤버가 정확히 A/B임을 확인한 별도 서비스 복구로 양쪽 나가기를 수행했다. 이후 비동기 네트워크 시작 전 lifetime window를 만들어 결과 기록과 finally가 완료되도록 했다. 다음 작성창 비교 실패는 WinUI 줄바꿈 표현 차이였으며 비교 정규화 후 실제 송신이 통과했다. 사진 메타데이터 assertion은 제품 수정 전 실패하고 수정 후 통과했다.

읽기 전용 코드 리뷰에서 초대 수락 전의 오래된 룸 참조와 정리 query 실패 시 미디어 경로 유실 위험을 발견했다. 멤버를 다시 읽고 미디어 경로를 즉시 기록한다. query 실패 시 룸 나가기를 보류해 복구 근거를 보존한다. 오류 출력은 서버 상태/code 또는 예외 타입만 남긴다.

최종 소스의 대화 전용 WinUI 7개는 `ui-shell-8b5d2aa8cd144691832e4a75c3d6f6be`에서 통과했다. 정상 x64 Release 빌드 경고·오류는 0이다. Core 283/App 339 통과는 대화 표시 변경의 기록을 따른다. 전체 UI suite의 이전 키보드 foreground 실패는 이 실제 서버 검증으로 해소됐다고 주장하지 않는다. 실제 카메라·마이크·Mac 상대 기기·ARM64 기기 및 모든 DPI/테마의 완전 일치는 남아 있다.

반복 실행은 `windows/scripts/test-ui-owned-live.ps1`에 기존 소유 세션 폴더·소유 fixture 폴더·명시적인 모니터를 전달한다. 폴더는 `windows/artifacts` 안에 있어야 한다. 이 문서 시점 설치본은 0.4.9이며 소스 수정은 다음 설치 후보에 포함한다. 전체 제품 목표는 계속 진행 중이다.
