# Windows 계정 관리 연결 검증

일반 설정에 저장 계정 목록, 전환, 명시적인 새 계정 추가와 로컬 삭제를 연결했다. 활성 계정은 닉네임·짧은 ID·사용 중 표시로 구분한다. 추가와 삭제에는 취소를 기본값으로 하는 확인창을 제공한다. 삭제는 서버 계정 삭제가 아니며, 마지막 계정을 지우면 설정에서 사용자가 새 계정을 추가해야 한다.

전환은 기존 클라이언트의 인증/세션 저장을 정리하고 HTTP 작업을 취소한 뒤 카메라·빠른 전송·수신 observer·realtime·재생 작업을 종료한다. 기존 메신저 타이머와 창 이벤트를 해제하고 같은 메인 HWND에 새 coordinator와 메신저를 구성한다. 이로써 준비된 시작 UID, 룸·초안과 메모리 ledger가 이전 계정에서 넘어가지 않는다. 기존 영구 알림 중복 방지는 유지한다. 계정 파일 변경에 실패하면 저장된 계정으로 다시 시작하고 새 설정 창에 실패/재시도 안내를 남긴다.

Mac의 저장 계정 및 삭제 의도를 참고했다. Mac 소스의 닉네임 기반 숨은 다중 계정 gate는 이 Windows 구현에 적용하지 않았다. 승인된 Windows 전략의 계정 관리/복구를 일관되게 제공하며, 빈 계정 상태에서 추가 경로를 숨기지 않는다. 닉네임 갱신은 계정 목록에도 반영한다.

검증:

- Core Release 264개 통과: 소유한 임시 파일과 합성 HTTP로 계정 보존 및 이전 클라이언트 요청 취소/후속 인증·RPC·추가 차단을 확인.
- App Release 310개 통과: 계정 선택, 실패 시 목록 보존과 민감한 오류 상세 비노출, 진행 중 중복 명령 차단.
- 실제 WinUI 160개 통과: 실제 선택 binding/전환 버튼, 추가·삭제 확인창의 취소·승인, 메신저 교체 시 HWND 보존/초안 초기화. `windows/artifacts/ui-shell-f89e4b46de504eefaccdc86f4af77458`에 합성 화면 결과를 기록했다.
- 정상 x64 Release 빌드: 경고 0개, 오류 0개.

운영 Supabase와 사용자 계정·캡처 장치를 사용하지 않았다. 실제 계정 간 영상 송수신을 포함한 종합 QA는 남아 있다. 업데이트와 설치 EXE는 별도 후속 단계다.
