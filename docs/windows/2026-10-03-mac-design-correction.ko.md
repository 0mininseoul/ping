# Mac 디자인 반영 누락과 Windows 화면 교정

사용자가 실제 디자인을 지적한 뒤 원본 코드를 다시 대조했다. Mac 코드의 일부 토큰/촬영 의미를 참조했지만 제품 화면 전체를 충실히 옮기지 못했다. 기능/설치 검사 통과를 UI 완성도의 증거로 취급한 것이 문제였다. Windows 룸 관리 창은 `Rooms`, `Up`, `Down`, raw 사용자 ID 입력과 생성·검색·초대 관리 폼을 동시에 펼친 이전 데모 형태를 유지하고 있었다.

## 반영한 원본과 변경

| Mac 원본 | Windows 교정 |
|---|---|
| RoomManagerWindow / RoomDetailView | 작은 룸 사이드바와 간단한 룸 제목·인원 헤더. 큰 로고/슬로건과 대화 영역 외곽 카드를 제거. 메인 기본 크기 1060×720 → 640×620 DIP. |
| ChatMessageRowView / ChatMessageBubbleLayout | 280pt 메시지 최대 폭, 11/6pt 내부 여백, 14pt 말풍선. 발신 파란색/흰 글자, 수신 회색. 내 이름을 반복하지 않으며 시간은 메시지 tooltip으로 확인. |
| MessageRowView | 얼굴 60×60 원형 썸네일, 화면 영상 폭90 및 저장 비율(0.5~3.0), 모서리8. 큰 영상 카드/모드 레이블 제거. 재생/저장/답장/반응 연결 보존. |
| ChatComposerView | 입력 최소36, 원본 12/8 여백과 작은 첨부·전송 버튼. 상시 키보드 안내 줄 제거. Enter/Shift+Enter/IME 처리 보존. |
| RoomManager의 별도 생성·검색 진입 | Windows 관리 창은 룸/찾기/초대로 나누어 필요한 폼만 표시. raw UID 입력 제거, 닉네임 검색과 기존 초대 서비스 연결 유지. 한국어 상태 안내. |

Windows 시스템 글꼴·창 조작·고대비 테마를 유지한다. 사용자 지정 macOS accent 색과 OS별 material 렌더링을 완전히 같게 구현했다는 뜻은 아니다. 관리 탭은 Windows의 기존 기능을 보존하며 폼 노출을 줄이는 중간 교정이고 Mac의 검색 sheet/멤버 popover까지 모두 동일해진 상태는 아니다.

## 확인한 것과 남은 것

App 309개 통과, 정상 x64 Release 빌드 경고/오류0. DISPLAY3의 실제 WinUI 진단 검사 175개를 통과했고 메인 밝게/어둡게, 작은 창, 룸 관리/찾기/초대 화면을 렌더링해 확인했다. 결과는 `windows/artifacts/ui-shell-35bb15e087b04065aff6f8669836b069/`에 있다. 기존 답장/전송/룸 변경/설정/재생/촬영 합성 검사를 유지했다. 사용자 계정이나 기존 룸에 테스트 메시지를 보내지 않았다.

현재 Mac 실행 화면을 이 PC에서 캡처하지 못했으므로 **현재 Mac 소스 기반 교정**으로 기록한다. 실제 Mac과 Windows의 같은 상태 스크린샷 비교와 전체 설정/온보딩/거울/리뷰 디자인 확인은 남아 있다. 오래된 검사 이미지를 현재 실행 앱의 감사 증거라고 주장하지 않는다.

Windows package version은 0.4.2.0으로 구분한다. 이전 0.4.1 EXE에는 이 디자인 수정이 없다. [CI 37032773315](https://github.com/0mininseoul/ping/actions/runs/37032773315)는 소스 `e09d7af`에서 성공했고 원래 인증서로 서명한 x64·ARM64 패키지와 EXE를 생성했다. 현재 파일은 `windows/dist/PingSetup-v0.4.2.exe`이다. SHA-256은 `E6310761307165CDF647714FE2319B36B7F74A388DAC85ABF0CCFC373253EFE4`, 213875782 bytes. 외부 EXE는 NotSigned, 내부 MSIX는 Valid다. 두 실제 관리 DLL에서 새 MessageBubble 타입을 확인했고 진단 타입/개인 데이터는 없다. 현재 실행 중인 0.4.0 앱을 강제 종료/재설치하지 않았으며 설치 성공/보존 실기 검증은 남아 있다. 공개 릴리즈·웹 다운로드는 교체하지 않았다.

## 0.4.3 설정·첫 실행 흐름

`SettingsScene.swift`의 작은 설정 창과 그룹별 항목을 560×440 Windows client로 옮겼다. 일반/저장 항목은 설명 왼쪽, 조작부 오른쪽의 16pt 카드이며 기존 설정 저장, 계정 확인/전환/추가/삭제, 기기 선택, 업데이트, QR 연결을 유지한다. 넓은 단축키 체크박스 표는 조합이 보이는 네 행과 펼친 편집부로 바꿨다. 수정 조합이 실제 행에 반영되며 기존 단축키 등록 경로를 사용한다.

첫 사용에는 `PairingView.swift`와 `PairingViewModel.swift`를 참고한 480×600 네이티브 안내가 뜬다. 원본 헤더 로고, 6단계 진행 표시, 환영 문구, 권한/닉네임/룸 연결 선택/생성/참여/완료 구성을 가져왔다. Windows Alt 단축키·트레이·권한 설정에 맞게 바꾸었다. 닉네임과 룸 이름은 원본의 큰 입력 카드, 안내/글자 수, Enter 제출을 사용한다. 룸 이름은 `RoomLimits.swift`처럼 16자로 제한하며 이모지를 자르지 않는다.

카메라·마이크가 없어도 메신저 설정을 계속할 수 있고, 이 안내를 권한 페이지 아래 고정 영역에 표시한다. 권한 확인은 사용자가 버튼을 누를 때만 수행한다. 기존 시스템 진단 목록은 별도의 ‘Ping 상태 점검’ 창이며 첫 사용 흐름으로 주장하지 않는다. 진단의 카메라 실패 문구도 전체 Ping이 비활성화됐다고 표시하지 않는다.

닉네임 저장과 룸 생성/검색/참여는 기존 익명 세션의 실제 서비스에 연결했다. 같은 이름 룸은 방장 닉네임으로 구분한다. 생성한 룸 ID를 보존하고 완료 시 해당 룸의 초대 조작부를 연다. 이미 룸 관리 창이 열려 있으면 오래된 목록을 다시 읽고 정확한 새 룸을 선택한다. 대상이 사라지면 다른 룸을 그대로 선택하지 않는다. 가입 완료는 가입한 룸 대화로 이어진다. 저장 실패 시 입력과 단계를 유지하며 중복 제출/창 닫기 취소를 방어한다.

Mac은 완료 payload에서 계정/룸 작업을 처리하지만 Windows는 닉네임 단계와 생성/참여 버튼에서 각각 서버 작업을 완료한다. 완료 화면은 성공 후에만 뜬다. 설정 룸 탭의 launcher, Windows 단축키 편집 방법, Mac의 sheet/popover, 시스템 material과 실제 실행 화면의 같은 상태 비교는 여전히 전체 parity 확인 항목이다. 이번 변경으로 모든 디자인이 같다고 주장하지 않는다.

App 322개, DISPLAY3 실제 WinUI 205개 통과. 최종 렌더는 `windows/artifacts/ui-shell-a5978e3aaf1f40109dc53e52c5b5402e/`이며 정상 x64 Release 빌드는 경고/오류0이다. 마지막 산출물 검증과 설치 파일 정보는 후속 배포 기록으로 업데이트한다. 코드 리뷰의 룸 식별/생성 후 초대/입력 카드/오래된 룸 목록 문제를 실제 동작 검사와 함께 교정했다. 현재 사용자 계정/룸에 시험 데이터를 쓰지 않았으며 설치·장치·Mac peer QA 미완료 상태도 유지한다.

[0.4.3 설치 후보](2026-10-03-windows-0.4.3-candidate.ko.md)를 생성했다. CI37039498491 성공, 두 실제 배포 DLL에서 새 안내 UI 존재와 진단 타입0개를 확인했다. 원래 인증서의 두 MSIX 서명이 Valid이며 PowerShell5.1 오프라인 payload 읽기 전용 검증도 통과했다. 외부 EXE는 NotSigned다. 실제 설치/기기 QA를 통과한 배포물이라고 표시하지 않는다.

## 0.4.4 룸 관리 폼 제거

남아 있던 새 룸/이름 변경 폼을 룸 화면에서 제거했다. 작은 제목·인원 헤더와 멤버 목록을 표시하고, +/이름 변경을 눌렀을 때만 입력창을 연다. 초대 링크는 헤더 조작에 두며 나가기는 확인창을 거친다. 위/아래 이동 버튼은 해당 행의 컨텍스트 메뉴로 옮겼다. 검색 결과의 방장 닉네임으로 같은 이름을 구분한다.

리뷰에서 확인한 룸 선택 변경 중 잘못된 대상 변경/나가기, 서비스의 UTF-16 이모지 제한, 생성 성공 후 목록 갱신 실패를 재생성 실패로 취급하는 문제를 교정했다. 입력 실패 시 입력과 재시도 조작을 유지한다. 실제 WinUI에서 바인딩·입력창·실패·룸 전환·컨텍스트 대상 행을 검증했고 DISPLAY3 216개, Core272/App323개가 통과했다. 최종 렌더는 `windows/artifacts/ui-shell-c85e8bffab1b4da2b13863dffe50a16e/`이다. 합성 테스트 데이터로 렌더링한 실제 WinUI 화면이며 Mac 실기와의 전체 디자인 비교는 아직 남아 있다.

현재 PC에서는 이전 앱이 종료된 뒤 0.4.3 EXE의 설치/제거/재설치가 모두 exit0으로 성공했다. 기존 계정·설정 파일 두 개가 세 단계 모두 원본 해시를 유지했다. 0.4.4 설치 파일과 실제 적용 결과는 후속 배포 기록에 남긴다.

[0.4.4 설치 후보](2026-10-03-windows-0.4.4-candidate.ko.md)를 생성하고 이 PC의 실제 EXE 업데이트도 exit0으로 완료했다. 최종 설치본은 0.4.4.0 / Status Ok이며 앱·네이티브 DLL이 검증한 MSIX와 동일하다. 기존 계정·설정은 최초0.4.0의 해시와 길이를 유지한다. 앱 자동 실행과 원격 계정 사용 검증은 수행하지 않았다.

## 0.4.5 메신저 안의 룸·연결 동선

Mac의 `RoomDetailView.swift`와 `RoomSearchView.swift`를 참고하여 메신저 +/검색과 헤더 멤버·초대 링크·이름 변경·나가기를 연결했다. 전체 사람 검색은 개인 대화를 연결하고 멤버 목록의 초대는 선택한 룸에 적용한다. 받은 초대의 수락/거절과 첫 사용 완료 후 만든 룸의 초대 화면도 메신저 안에서 동작한다. 사진·얼굴·화면 촬영은 작은 입력 메뉴에서 계속 사용할 수 있다. 설정의 별도 관리 진입점까지 제거했다는 뜻은 아니다.

목록 조회 실패 때문에 확인된 서버 변경을 재요청하는 문제를 생성·참여·개인 연결·이름 변경·나가기에서 방어한다. 나가기의 대상 검사는 닫힘 애니메이션 후가 아니라 확인 클릭 시 수행한다. 0.4.4 검사에서는 클릭 후 잠깐의 상태만 확인해 이 애니메이션 중 재선택 경로를 놓쳤고, 새 통합 검사에서 발견해 수정했다.

Core272/App333, DISPLAY3 WinUI243개와 정상 x64 Release가 통과했다. [0.4.5 설치 후보](2026-10-03-windows-0.4.5-candidate.ko.md)의 두 MSIX는 원래 인증서 서명 Valid이며 테스트 코드가 없다. 이 PC의 실제 EXE 업그레이드 exit0, 최종0.4.5.0 / Status Ok다. 설치 파일이 검증한 패키지와 같고 기존 계정 파일 두 개는 최초0.4.0 기준과 해시·길이가 같다. 실제 보존한 두 파일은 세션과 백업이다. 이전 기록의 ‘계정·설정 파일’ 표현은 이를 넓게 지칭했으며 저장된 설정 파일의 실기 보존을 입증한 것은 아니다. 전체 Mac 실기 시각적 대조와 기기 간 QA는 여전히 남아 있다.
