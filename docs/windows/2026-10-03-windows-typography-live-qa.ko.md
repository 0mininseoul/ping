# Windows 글꼴 재확인과 실제 서버 QA

검증 기준은 `ca1d191` 소스와 이 PC에 설치된 Windows 0.4.7.0이다. 이번 작업은 기존 후보의 확인이며 새로운 설치 버전을 만들지 않았다.

## 글꼴과 화면

사용자 요청에 따라 Windows 본문은 패키지에 포함한 Pretendard Variable을 사용한다. 본문 14 DIP / 줄 높이 21, 보조 글자 12 DIP / 줄 높이 18, 제목 SemiBold, 입력창 여백 가로 12 / 세로 8을 적용한 상태다. 설치된 글꼴과 소스의 SHA-256이 같다. macOS 시스템 글꼴은 변경하지 않았다.

DISPLAY3에서 새 진단 실행의 실제 WinUI 256개 검증이 통과했다. 대화창과 설정의 새 렌더를 직접 확인했다. 한글 본문과 줄바꿈에 잘림은 보이지 않았으며, Windows 아이콘 글꼴은 별도로 유지된다. 이번 확인은 100% 배율이며 모든 DPI에서의 가독성이나 접근성 준수 전체를 증명하지 않는다.

로컬 렌더: `windows/artifacts/ui-shell-0de3a809a45049f2a23b1576dbdbc322/`. 대화 내용은 소유한 fixture이며 실제 사용자의 대화나 Mac 실기 스크린샷이 아니다.

## 실제 Supabase 클라이언트 검증

설치 패키지의 구성으로 pinned Ping 프로젝트 `qxjtprxvjmaxlbtljcjw`에 접속했다. 앱에서 사용하는 C# Core 서비스와 두 개의 별도 익명 테스트 계정을 사용했다. 각 세션 경로를 ignored QA 폴더로 지정해 기존 설치 계정 파일을 사용하지 않았다. 다른 사람에게 초대나 메시지를 보내지 않았다.

실제 서버에서 기능 확인 18개와 정리 작업 8개가 성공했다.

- 초대 전송·수락, 양쪽 룸 연결, 이름 변경, 초대 링크의 URL 변환.
- 한글·이모지·여러 줄 채팅, 답장 참조, 반응 추가·조회·제거, 읽음 표시.
- 사진 업로드와 파일명·크기 전달, 수신자 다운로드와 원본 SHA-256 일치.
- 소유한 합성 3초 MP4 업로드, 위치·화면 모드·저장 불허 메타데이터 전달, 수신자 다운로드와 원본 SHA-256 일치.
- 수신자의 영상 읽음 표시가 발신자에게 반영되고, 읽고 알림 처리한 영상은 수신 대기 목록에서 사라짐.

테스트 메시지와 첨부 객체의 삭제 API, 두 계정의 룸 나가기를 실행했다. 별도 클라이언트를 다시 열어 두 세션이 복구되고 두 테스트 계정의 룸 목록이 비었음을 확인했다. 익명 계정 자체를 서버에서 삭제한 검증은 아니다. 두 QA 계정의 세션은 ignored 폴더에만 남겨 후속 검증에 재사용할 수 있다. 토큰·키·개인 데이터는 커밋하지 않았다.

로컬 결과: `windows/artifacts/live-owned-df6ddfe340984e7db4bb7fb744b28263/result.json`, `cleanup-readback.json`. 이 검증은 실제 Windows 서비스와 서버의 통신을 확인한다. UI로 두 앱을 조작한 E2E, Mac 상대 기기와의 송수신, 카메라·마이크 촬영 완료를 뜻하지 않는다. 얼굴 영상의 대화 안 확대 재생 등 남은 Mac 흐름 차이는 계속 구현해야 한다.
