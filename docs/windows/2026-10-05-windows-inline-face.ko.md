# Windows 대화 안 얼굴 영상 재생

Mac `InlinePlayerView.swift`와 `MessageRowView.swift`의 얼굴 영상 60pt 썸네일 → 128pt 원형 재생을 Windows 대화창에 적용한다. 화면+얼굴 영상은 기존 coordinator의 큰 외부 재생창 경로를 유지한다.

얼굴 영상을 누르면 대화 안에서 내려받아 재생한다. 다시 재생은 같은 플레이어와 파일을 재사용하며, 원형 영상을 누르거나 Esc로 접을 수 있다. 재생 완료 후 자동으로 사라지지 않는다. 다운로드·디코더 실패는 한국어 재시도 상태로 표시한다. 기존 실제 다운로드 서비스와 캐시·아카이브 경로를 사용한다.

플레이어는 대화창이 보유하고 타임라인의 현재 행에 연결한다. 행이 새로 만들어지는 새로고침에도 같은 MediaPlayer를 보존한다. 룸 변경·계정 detach·행 삭제 때 다운로드를 취소하고 미디어와 UI 참조를 비운다. 늦은 다운로드는 새 룸에 붙지 않는다. 로딩 중 다시 재생 메뉴는 중복 다운로드를 시작하지 않는다.

읽음은 현재 계정이 수신자이고 해당 룸을 보고 있을 때만 호출한다. 첫 요청이 진행 중이면 재생이 다시 끝나도 같은 읽음 요청을 보내지 않는다. 이전 영상의 늦은 응답이 다음 영상의 읽음 상태를 바꾸지 않는다. 실제 실패한 읽음 요청은 다음 재생 완료 때 재시도할 수 있다. 자동 얼굴 회신이나 수신 알림 경로는 이 히스토리 재생으로 실행하지 않는다.

## 검증

- 기존 face 클릭이 외부 경로를 호출하는 실제 WinUI 실패를 먼저 확인했다.
- 로딩 중 context replay 중복 다운로드와 이전 expansion의 늦은 읽음 응답 문제도 각각 실패를 확인한 뒤 수정했다.
- DISPLAY3의 실제 WinUI 274개 검증이 통과했다. 3초 합성 MP4의 디코더 크기, 끝까지 재생, 읽음 호출, 128 DIP 원형 clip, 동일 플레이어·다운로드 유지, 재생·접기·재시도·룸/계정 변경, 중복 요청 방어를 포함한다.
- App338개 검증과 정상 x64 Release 빌드 경고/오류0을 확인했다. 수신자·현재 룸 제한은 별도 portable 서비스 호출 검사도 포함한다.
- 렌더: `windows/artifacts/ui-shell-48e88fe46908470b8e9581c2bd5ec7a7/`. 합성 영상과 테스트 대화는 소유한 fixture다.

RenderTargetBitmap PNG에는 MediaPlayerElement의 영상 픽셀이 포함되지 않는다. 원형이 빈 배경으로 보이는 PNG는 레이아웃·텍스트 확인용이다. 영상 디코드와 실제 재생 종료는 네이티브 플레이어와 callback으로 별도 확인했다. [Microsoft의 캡처 제한](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.media.imaging.rendertargetbitmap.renderasync?view=windows-app-sdk-2.0)을 따른다. OS 캡처 제외 정책을 끄거나 영상 프레임을 화면에 합성해 검증 이미지를 만들지 않았다.

현재 카메라·마이크·Mac 상대 기기 검증은 남아 있다. 전체 제품 완성을 뜻하지 않는다. 이번 후보의 Windows 버전은 0.4.8.0이며 패키지와 실제 설치 결과는 후보 문서에서 확인한다.
