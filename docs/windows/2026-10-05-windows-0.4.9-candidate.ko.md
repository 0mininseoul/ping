# Ping Windows 0.4.9 설치 후보

Windows 소스는 `a8d65712bab4359dc59afb9055f296a279d589dd`다. Mac 기준 `5b21c1962de83d1e0d6c08ba8619802cbd53280b`(0.3.80)의 사진 드롭을 대조해 Windows 대화창 드롭과 사진 붙여넣기를 추가했다. 작성창에서 48 DIP 미리보기·파일명·문구를 확인하고 Enter로 전송한다. 클립보드의 이미지 전용 Ctrl+V·Shift+Insert와 일반 텍스트 붙여넣기를 지원한다. 상세 UX 결정과 수명·제한은 [사진 입력 문서](2026-10-05-windows-photo-input.ko.md)를 따른다.

원본 사진을 보존하고 소유 복사본을 사용한다. 실패한 전송은 사진과 문구를 유지하며 성공·취소·교체·계정 전환은 쓰지 않는 복사본을 정리한다. 룸마다 작성 중인 첨부를 유지하고 늦은 읽기가 다른 룸에 붙지 않는다. 4K BMP 스크린샷은 PNG 정규화 후 저장소의 15 MB 제한을 검사한다. 이전 후보의 Pretendard, 사진 확대, 128 DIP 원형 인라인 얼굴 재생, 룸 관리와 첫 사용 안내도 포함한다.

## 검증과 패키지

- DISPLAY3 실제 WinUI 297개 검증이 통과했다. 이미지 전용 클립보드의 실제 키 입력과 소유 진단 source의 실제 마우스 드롭, reader·미리보기·채팅 전송 payload·실패 후 재시도·파일 보존/정리를 포함한다. 결과와 라이트/다크 렌더는 `windows/artifacts/ui-shell-4664a4c58ff840cb9ec117084549aa35/`다. 외부 File Explorer·브라우저의 모든 형식을 검사한 것은 아니다.
- Core 272 / App 338개 검증과 정상 x64 Release 빌드 경고/오류 0을 확인했다. [CI 37253883262](https://github.com/0mininseoul/ping/actions/runs/37253883262)가 같은 소스로 해당 검증과 x64·ARM64 MSIX 및 EXE를 생성했다.
- 두 MSIX의 기존 인증서 서명은 `Valid`다. manifest identity/버전/CPU, 네이티브 DLL CPU, 새 사진 reader·드롭·붙여넣기, 기존 메신저·미리보기·인라인 얼굴 플레이어·룸 관리·첫 사용 안내, Pretendard 원본과 라이선스를 확인했다. 진단 타입과 개인 계정 데이터는 없다.
- 패키지 결과는 `windows/artifacts/ci-37253883262/package-verification.json`이다. ARM64는 패키지 검사만 수행했으며 ARM64 실기 실행은 검증하지 않았다.

설치 파일은 `windows/dist/PingSetup-v0.4.9.exe`, 220,124,264 bytes(약 210 MiB)다. 외부 EXE는 `NotSigned`, 내부 MSIX는 기존 인증서 서명 `Valid`다.

## 이 PC의 실제 설치

EXE 업데이트 0.4.8 → 0.4.9는 exit 0, 패키지 0.4.9.0 / Status Ok다. 설치된 앱·네이티브 DLL·Pretendard·라이선스는 검증한 x64 MSIX와 해시가 같다. 시작 메뉴, 제거 프로그램과 제거 항목 0.4.9를 확인했다.

계정 파일 두 개(세션과 백업)는 설치 전과 최초 0.4.0 기준에 대해 해시·길이가 같다. 별도 설정 파일이 없으므로 설정 값 보존의 실기 검증을 뜻하지 않는다. 정상 설치본은 자동 실행하지 않았다. 결과는 `windows/artifacts/install-049-3eda65d658214e2caf2eb1976ae5c821/upgrade-verification.json`이다.

클립보드 진단의 첫 OLE 복원 시도는 Windows 오류로 실패해 그 시도의 원래 클립보드 내용 보존은 확인하지 못했다. 이후 메모리 snapshot과 WinRT 복원 방식은 성공했고 마우스 위치도 복원했다. 계정 파일은 이 진단에서 변경하지 않았다.

공개 릴리즈·웹 다운로드는 교체하지 않았고 공개 채널은 0.3.46이다. 실제 서버의 두 소유 QA 계정으로 서비스 흐름을 검증한 이전 결과는 [QA 기록](2026-10-03-windows-typography-live-qa.ko.md)에 있다. 네이티브 UI와 실제 서버를 함께 사용한 전체 QA, 현재 Mac의 1:1 발신자 이름 숨김과 모든 본문 링크, DPI·기기 대조는 남아 있다. 카메라·마이크·Mac 상대 기기가 없어 실제 얼굴 녹화와 Mac↔Windows 송수신은 완료로 주장하지 않는다. 전체 제품 목표를 계속 진행한다.
