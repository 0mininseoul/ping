# Windows 대화 표시와 본문 링크

Mac 기준 `5b21c1962de83d1e0d6c08ba8619802cbd53280b`의 `RoomTimelineView`와 `SelectableTextView`를 대조했다. 1:1은 발신자 이름을 숨기고 3명 이상 룸에서 받은 채팅·영상에 이름을 표시한다. 같은 룸의 멤버 정보만 갱신되어도 기존 행의 표시가 바뀐다.

본문은 네이티브 WinUI `TextBlock`의 선택·복사 기능을 유지하면서 각 URL·이메일을 `Hyperlink`로 표시한다. HTTP(S), WWW·일반 도메인과 이메일을 인식한다. 이메일은 메일 처리기로 연결하고 웹 미리보기 요청은 HTTP(S)만 사용한다. 이모지 뒤의 UTF-16 범위, 줄바꿈·문장 부호·URL 안의 괄호를 보존한다. Mac의 NSDataDetector와 동일한 판별기를 구현한 것은 아니다. 잘못된 이메일은 일반 텍스트로 남겨 대화 로딩을 막지 않는다.

이전 0.4.9에 포함한 Pretendard Variable, 본문 14 DIP/줄 높이 21 DIP, 캡션 12 DIP/18 DIP를 사용한다. 받은 링크는 강조색, 보낸 링크는 말풍선의 흰색 본문색이다. 라이트·다크 렌더를 확인했다.

## 검증

- Core 283개와 App 339개 검증. 잘못된 이메일은 수정 전 실패를 확인했다.
- DISPLAY3의 대화 전용 실제 WinUI 검증 7개 통과: `windows/artifacts/ui-shell-dc7988b2c1684065b79098f2f6029ceb/`. 이름 표시·개별 URI·선택 원문·테마색·라이트/다크 렌더를 확인했다. 외부 브라우저나 메일 앱을 실제 실행하지 않았다.
- 전체 UI 검증 두 번은 변경하지 않은 사진 입력의 실제 키 입력에서 foreground guard가 실패했다. 해당 실행의 이번 대화 검증은 통과했으나 전체 성공으로 주장하지 않는다. 기록은 `ui-shell-b4bcb6d87fab462bbc3090ac7a65aafc`와 `ui-shell-49b836be419f47d2bbfb295003203f9b`다. 클립보드 복원 finally는 완료했다. 이전 0.4.9 전체 297개 통과 결과는 별도다.
- 읽기 전용 리뷰에서 잘못된 이메일의 URI 예외를 발견해 `TryCreate`와 회귀 검증으로 수정했다.

이 변경 시점의 설치본은 0.4.9이며, 소스 변경이 설치되었다는 뜻은 아니다. 실제 UI와 서버의 연결 검증 후 다음 설치 후보에 묶는다. Mac 소스와 백엔드 정책·스키마는 변경하지 않았다.
