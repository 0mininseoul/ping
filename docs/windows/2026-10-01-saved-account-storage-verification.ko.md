# Windows 저장 계정 기반 검증

기존 `SupabaseSession.json`을 읽어 저장 계정 목록으로 이행하고, 활성 세션과 목록을 같은 파일에 원자적으로 기록한다. 기존 파일의 활성 세션 필드는 유지한다. 계정 추가·전환·로컬 제거·닉네임 저장 API를 제공하며, 갱신은 해당 계정의 토큰만 교체한다.

손상된 파일이나 인증 갱신 실패로 새 계정을 자동 생성하지 않는다. 마지막 저장 계정을 제거한 상태는 최초 실행과 구분하고 명시적인 새 계정 추가를 요구한다. 파일 저장에 실패한 전환은 기존 계정을 유지하며, 새 익명 계정 생성 후 저장 실패의 재시도는 같은 프로세스에서 생성한 세션을 재사용한다. 서버 계정 삭제나 백업 파일의 자격 증명 제거 기능은 아니다.

검증 결과:

- Core Release 263개, App Release 307개 검사 통과. 기존 파일 이행, 재시작 후 두 계정 보존, 저장 실패, 마지막 계정 제거, 계정별 갱신 및 잘못된 UID의 갱신 응답 거부를 합성 HTTP/소유한 임시 파일로 확인했다.
- 실제 WinUI fixture 150개 통과. 결과: `windows/artifacts/ui-shell-ab38f4ab6b34428394774e915eb152dd`.
- 정상 x64 Release 빌드 통과: 경고 0개, 오류 0개.

이번 단계는 저장·인증 API의 기반 구현이다. 설정 화면에서 계정을 관리하고 전환 전에 기존 송수신·캡처 작업을 정리하는 연결은 다음 단계에 남아 있다. 실제 사용자 계정, 운영 Supabase, Mac 간 전환은 테스트하지 않았다. 업데이트와 설치 EXE 작업도 계속 진행한다.
