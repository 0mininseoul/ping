# Windows 설정·외관·알림 소리 검증

2026-10-01, `codex/windows-parity`. 전체 Windows parity 작업 중 설정 단계의 구현 결과다. 기기 연결·계정·업데이트·최종 설치 EXE는 다음 단계에 남아 있다.

## 변경

- 일반·단축키·룸·저장·정보 설정을 스크롤 가능한 한국어 화면으로 정리했다. 설정 탭은 닫을 수 없으며 필요한 너비에 맞게 배치된다. 현재 창의 DPI와 작업 영역에 맞춰 초기 클라이언트 크기를 정하고 일반 Windows 창처럼 크기를 변경할 수 있다.
- 시스템/라이트/다크와 알림 소리 기본/없음을 기존 `QuickSendSettings.json`의 새 필드로 저장한다. 기존 파일에서 필드가 없으면 시스템 테마와 소리 켜기가 기본값이다. 기존 기본 룸·저장 권한·빠른 전송·자동 재생 설정을 유지한다.
- 기존 창과 이후 생성하는 창에 같은 외관 선택을 전달하고 주요 표면·텍스트·캡슐 색을 동적으로 변경한다. 영상·채팅 알림 생성 시 현재 소리 설정을 읽어 무음이면 Windows toast XML에 `audio silent="true"`를 추가한다. 알림 중복 방지와 클릭 연결은 유지한다.
- 기존 닉네임 저장·핫키 설정·시작 프로그램·저장 폴더 동작을 유지했다. 정보 탭의 릴리즈 안내는 실제 GitHub 릴리즈 페이지로 연결하며 자동 업데이트 구현을 대신하는 완료 표시를 하지 않는다.

## 검증 결과

| 검사 | 결과 |
| --- | --- |
| Core Release 테스트 | 254 통과 |
| App Release 테스트 | 301 통과, 기존 JSON 마이그레이션·저장 보존·영상/채팅 toast XML 검사 포함 |
| 실제 WinUI fixture | 139 통과 |
| 정상 x64 Release 빌드 | native/Core/WinUI 모두 경고 0, 오류 0 |
| 변경 파일 공백 검사 | 통과 |

WinUI 아티팩트: `windows/artifacts/ui-shell-884251a612a64a9b9705c36fda4e5265/`. 실제 설정 컨트롤을 조작해 자동 재생·소리 저장, 작은 클라이언트에서 수직 스크롤, 라이트/다크의 설정 창·기존 메신저 반영, 새 창의 테마 상속, 시스템 모드 복원을 확인했다. `settings-light.png`와 `settings-dark.png`를 직접 확인했으며 설정 탭의 불필요한 닫기 버튼을 제거했다. 기존 합성 영상 재생·녹화 검사는 같은 fixture에서 통과했다.

정상 실행 바이너리: `windows/src/Ping.Windows.App/bin/x64/Release/net10.0-windows10.0.26100.0/win-x64/Ping.Windows.App.exe`. 이 결과는 설치 EXE나 서명된 최종 릴리즈를 의미하지 않는다.

## 남은 범위

검사는 앱이 소유한 합성 데이터와 창을 사용했다. 실제 사용자 세션·운영 backend·카메라·마이크·화면 캡처를 사용하지 않았다. Windows 알림 센터의 실제 소리 출력, 여러 모니터의 DPI 전환과 고대비 모드, Mac와의 실제 송수신, 설치/업데이트/ARM64 QA는 별도로 남아 있다. 일부 녹화 표시의 의도적인 고정 색상은 유지한다.

다음은 선택한 카메라·마이크를 녹화 lease에 고정하고, 기기 탭에서 Mac와 같은 QR handoff를 제공하는 단계다. Mac의 실제 `SupabaseJSON.encoder`는 날짜를 ISO 8601로 인코딩하므로 handoff를 Swift 기본 날짜 숫자 형식으로 구현하면 안 된다.
