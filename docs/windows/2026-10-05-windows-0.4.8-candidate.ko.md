# Ping Windows 0.4.8 설치 후보

Windows 소스는 `84ca123aeb9d674f7303be656f96326210b050fe`다. Mac 기준 `5b21c1962de83d1e0d6c08ba8619802cbd53280b`(0.3.80)의 얼굴 영상 대화 재생을 대조해 128 DIP 원형 인라인 플레이어를 추가했다. 대화 안에서 재생·다시 재생·접기·실패 후 재시도를 처리한다. 룸·계정 변경은 다운로드와 플레이어를 정리하고, 새로고침은 재생 중인 플레이어를 보존한다. 상세 내용은 [인라인 얼굴 영상 문서](2026-10-05-windows-inline-face.ko.md)를 따른다.

Pretendard, 대화 사진 확대 보기, 메신저 안의 룸 관리와 첫 사용 안내도 포함한다. 실제 서버에 두 소유 QA 계정으로 텍스트·사진·영상·회신·반응·읽음·룸 연결을 검증하고 생성한 메시지와 저장 객체를 정리한 결과는 [실제 서비스 QA 기록](2026-10-03-windows-typography-live-qa.ko.md)에 있다. 이 검증은 Mac 상대 기기와의 송수신 검증을 대신하지 않는다.

## 빌드와 패키지

- DISPLAY3 실제 WinUI 274개 검증, App 338개 검증, 정상 x64 Release 빌드 경고/오류 0을 확인했다. 로컬 렌더와 진단 결과는 `windows/artifacts/ui-shell-48e88fe46908470b8e9581c2bd5ec7a7/`에 있다. 영상 픽셀은 RenderTargetBitmap 캡처 대상이 아니므로 재생은 디코더와 종료 callback으로 별도 확인했다.
- [CI 37251296746](https://github.com/0mininseoul/ping/actions/runs/37251296746)가 같은 소스로 Core 272 / App 338개 검증과 x64·ARM64 MSIX 및 EXE를 생성했다.
- 두 MSIX의 기존 인증서 서명은 `Valid`다. manifest identity/버전/CPU, 네이티브 DLL CPU, 새 인라인 플레이어와 로딩 방어, 사진 미리보기, 메신저·룸 관리·첫 사용 안내, Pretendard 원본과 라이선스를 확인했다. 진단 타입과 개인 계정 데이터는 패키지에 없다.
- 패키지 검사 기록은 `windows/artifacts/ci-37251296746/package-verification.json`과 `verify-packages.ps1`이다. ARM64 패키지는 생성·검사했으나 ARM64 기기 실행은 검증하지 않았다.

설치 파일은 `windows/dist/PingSetup-v0.4.8.exe`, 220,115,683 bytes(약 210 MiB)다. 외부 EXE는 `NotSigned`, 내부 MSIX는 기존 인증서 서명 `Valid`다.

## 이 PC의 실제 설치

EXE 업데이트 0.4.7 → 0.4.8은 exit 0, 패키지 0.4.8.0 / Status Ok다. 설치된 앱·네이티브 DLL·Pretendard·라이선스는 검증한 x64 MSIX와 해시가 같다. 시작 메뉴, 제거 프로그램과 제거 항목 0.4.8을 확인했다.

계정 파일 두 개(세션과 백업)는 설치 전과 최초 0.4.0 기준에 대해 해시·길이가 같다. 별도 설정 파일이 없으므로 설정 값 보존의 실기 검증을 뜻하지 않는다. 정상 설치본은 자동 실행하지 않았다. 결과는 `windows/artifacts/install-048-6e5e3e735f3549498fda6b23345b35a1/upgrade-verification.json`이다.

공개 릴리즈·웹 다운로드는 교체하지 않았으며 공개 채널은 0.3.46이다. 카메라·마이크·Mac 상대 기기가 없어 실제 얼굴 녹화와 Mac↔Windows 송수신 검증은 남아 있다. 사진 드래그/붙여넣기 등 확인된 Mac 사용 흐름 차이와 DPI·전체 디자인 대조도 계속 진행한다. 전체 제품 완료로 표시하지 않는다.
