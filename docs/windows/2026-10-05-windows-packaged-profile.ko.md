# Windows 설치본 계정 경로와 알림 검증

정상 설치된0.4.12를 기존 QA 계정 두 개로 검증했다. 사용자 계정과 다른 계정임을 확인하고 일반/패키지 저장소를 모두 임시 보관했다. 테스트 종료 시 원래 네 파일을 바이트 그대로 복원하고 QA 메시지와 두 룸의 멤버십을 정리했다. 원래 사용자 세션은 네트워크 인증에 사용하지 않았다.

첫 검사에서 일반 `%LOCALAPPDATA%/Ping`에만 넣은 QA 세션을 설치본이 읽지 않았다. 패키지 `LocalCache/Local/Ping`에 새 익명 세션을 만들었다. 새 계정에 메시지를 보내지 않았다. 이 실패는 알림 수신 실패의 근거가 아니다. 해당 실행에는 의도한 수신 계정이 연결되지 않았다. 기존0.4.12 업데이트에서 일반 저장소 파일의 해시 보존만 확인한 결과로 설치본 런타임 계정 연속성을 주장할 수 없다.

설치 단계에서 기존 일반 저장소의 세션·설정을 패키지 저장소로 복사하도록 수정했다. 기존 패키지 계정이 있으면 그대로 유지하며, 패키지 백업만 있으면 먼저 그 계정을 복원한다. 보존과 복원도 세션/백업을 같은 저장소 묶음에서 선택해 현재 계정과 예전 계정의 백업이 섞이지 않도록 했다. 제거 후 복원 시 현재 묶음에 백업이 없으면 예전 일반 저장소 백업을 제거한다.

Windows PowerShell5.1에서 의미 있는 실패를 먼저 재현했고 수정 뒤 보존 검사12개를 통과했다. `windows/artifacts/packaged-notification-qa/account-group-red.log`와 `account-group-green.log`가 근거다. 두 번의 정적 코드 검토에서 계정 묶음 문제를 수정한 뒤 확인된 Critical/Important 문제는 없었다. 동시에 실행되는 비패키지 앱의 파일 쓰기는 검증 범위 밖이다.

수정된 초기화를 QA 프로필에 적용한 두 번째 정상 설치본 실행은 기존 QA 수신 계정과 일치했다. 상대 QA 계정에서 다른 룸으로 보낸 텍스트가 읽지 않음1로 조회됐고, Windows 알림 기록에 해당 메시지 ID의 실제 Ping 알림1개가 등록됐다. 근거 폴더는 `windows/artifacts/packaged-toast-b73804bd513748abb0128e06aad1fcfd`이며 `effective-identity-diagnostic.json`, `before-warm.json`, `toast-history.json`, `profile-restoration.json`, `server-cleanup.json`을 따른다. 개인정보가 담긴 세션 파일과 ID는 커밋하지 않는다.

이 결과는 정상 설치본의 실제 수신 계정 및 OS 알림 생성 증거다. OS 알림의 실제 클릭, 종료 상태의 알림 활성화와 대화방 이동을 검증한 결과는 아니다. 자동화가 알림 창을 선택할 수 없었으며 캡처 제외를 우회하지 않았다. Mac 상대, 카메라/마이크, ARM64 실제 기기와 혼합 DPI 검증도 남아 있다.0.4.13 EXE 생성 및 실제 설치 결과는 후속 후보 안내에 기록한다.

[0.4.13 후보 안내](2026-10-05-windows-0.4.13-candidate.ko.md)에 EXE 업데이트·제거·재설치와 정상 재설치본의 실제 QA 계정/알림 생성 결과를 기록했다. 원래 일반/패키지 저장소 일곱 파일은 검사 종료 후 바이트 그대로 복원했다.
