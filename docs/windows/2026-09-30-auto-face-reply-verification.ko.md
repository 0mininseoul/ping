# Windows 자동 얼굴 답장 검증 기록

작성일: 2026-09-30. 구현 커밋: `a6f56fa`, `bbd0dd5`, `c3bbdce`, `db68bc1`. 전체 Windows 완성 목표 중 자동 답장·카메라 수명 관리 단계의 기록이다.

## 구현한 동작

- 실행 중 도착한 새 영상에만 3초 얼굴 답장을 시도한다. 원래 발신자 한 명에게 보내며 자동 답장 영상에는 다시 답장하지 않는다. 시작·재연결·히스토리 영상, 오래된 영상, 중복 도착, 잠금·절전 상태, 허용되지 않은 권한, 이미 사용 중인 카메라는 제외한다. 받은 영상 자동 재생 설정과 독립적으로 동작한다.
- 수동 거울, 화면+얼굴 녹화, 권한 검사와 자동 답장은 공통 카메라 사용권을 적용한다. 수동 요청이 자동 답장을 중단해도 기존 카메라 작업의 정리가 끝난 후에 사용권을 넘긴다. 계정 변경과 정상 앱 종료도 진행 중 작업을 기다린다.
- 녹화 전후와 서버 메시지 생성 직전에 계정·영상 신선도·중단 상태를 재확인한다. 원본 위치와 저장 허용 설정을 유지하며 `is_auto_reply_value=true`로 생성한다. 이미 서버에 생성됐을 수 있는 모호한 네트워크 실패는 자동 재전송하지 않고 업로드를 보존한다.
- 232×56 DIP 표시창에 빨간 녹화 상태, 발신자, 진행 상태를 보여준다. 작업 영역에서 20 DIP 여백을 유지하고 입력 포커스를 가져오지 않는다. 결과에 관계없이 표시창·임시 영상·카메라 사용권을 정리한다.
- 카메라 초기화와 녹화의 WinRT 취소가 실제로 끝날 때까지 기다린다. 화면+얼굴 미리보기 종료 중 Enter가 반복되거나 창을 닫아도 같은 종료 작업을 기다린다.

## 검증 결과

| 검증 | 결과 |
|---|---|
| Core 자동 검사 | 209개 통과 |
| App 자동 검사 | 259개 통과 |
| 실제 WinUI fixture | 63개 통과 |
| x64 native / 일반 Release / MSIX 빌드 | 경고 0, 오류 0 |
| 일반 Release 진단 코드 제외 | `UiSmokeRunner`, `PlaybackSmoke`, `AutoReplySmoke`, `CaptureLifetimeSmoke` 없음 |
| 독립 전체 단계 코드 리뷰 | 확인된 종료 경로 두 건 수정 |

화면+얼굴 미리보기의 종료 작업 진입을 지연시키고 Enter를 반복하는 실제 WinUI 검사에서, 정리가 끝나기 전에 새 녹화를 시작하는 실패를 재현했다. 종료 작업 공유와 입력 중복 방지 후 동일 검사가 통과했다. 창을 닫는 경로에서도 정리가 끝나기 전에는 사용권을 반환하지 않는 것을 검사했다.

두 거울창의 XAML과 생성자에 함께 있던 닫기 이벤트 등록을 XAML 한 곳으로 정리했다. 실제 종료 검사는 통과했다. 중복 등록 자체에 의한 예외는 이번 fixture에서 별도로 재현되지 않았으므로 이를 재현 완료라고 주장하지 않는다.

실제 화면+얼굴 창 생성 중 기존 `Clip` 리소스 할당의 `XamlParseException`도 발견했다. 창별 inline `RectangleGeometry`로 바꾼 뒤 동일 창 생성 검사가 통과했다. 관련 API 형식은 [Microsoft UIElement.Clip 문서](https://learn.microsoft.com/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.uielement.clip)를 참고했다. 진단 기록은 종료 후 추가 오류가 최초 원인을 덮어쓰지 않도록 보존한다.

검사는 격리된 fake 계정·서비스와 지연된 카메라 어댑터를 사용했다. 표시창은 현재 200% 화면 배율에서 실제 native 크기·여백·비활성 스타일·표시 텍스트·타이머 정리를 검사했다. 전원/세션 이벤트 등록과 자체 창으로 전달한 잠금 알림을 검사했으며, 실제 장치 절전 시험을 대체하지 않는다.

## 남은 개발과 실기 검증

실제 카메라·마이크의 3초 녹화, 물리적 절전/잠금, 운영 Supabase 업로드, Mac 교차 송수신, ARM64 장치, 서명된 EXE 설치는 아직 검증하지 않았다. 사용자 계정 파일과 운영 서버 설정은 테스트에서 변경하지 않았다.

캡처창의 DPI와 화면 확대·이동, 계정/기기 연결, 최신 설정·외관·소리, EXE 설치·업데이트, 실기 QA가 계속 남아 있다. 종료된 프로세스의 원격 push도 별도 서버 경로가 필요한 미완료 항목이다. unsigned MSIX 빌드는 최종 EXE 설치 프로그램 완성을 뜻하지 않는다.
