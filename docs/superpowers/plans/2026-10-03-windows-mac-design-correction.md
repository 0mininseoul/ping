# Windows 화면을 현재 Mac 제품 구조로 교정

사용자는 기존 Windows 데모 디자인을 버리고 최신 Mac UI/UX를 기준으로 만들 것을 처음부터 요청했다. 현재 구현은 기능·설치 검증에 치우쳤으며 특히 RoomManagerWindow의 영어 폼 화면과 메인 창의 과한 카드/브랜딩이 그 요구를 충족하지 못했다. 기존 승인 범위에서 화면을 교정한다.

## 직접 참고하는 현재 원본

- `Ping/UI/Setup/RoomManagerWindow.swift`: 작은 룸 사이드바, 룸별 대화, 생성·검색 별도 진입점.
- `Ping/UI/Setup/RoomDetailView.swift`: 16pt/10pt 헤더 여백, 얇은 구분선, 작은 룸 제목/멤버 수.
- `Ping/UI/History/ChatMessageRowView.swift`: 내 메시지 파란색/흰 글자, 상대 메시지 회색, 14pt 말풍선, 타이트한 간격.
- `Ping/UI/History/ChatComposerView.swift`: 36pt 입력, 30pt 원형 첨부/전송, 12pt/8pt 여백.
- `Ping/UI/Glass/PingDesign.swift`: adaptive accent와 dark surface. Windows 시스템 글꼴·창 제어를 사용한다.

## 이번 작업

1. 메인 대화를 compact split layout으로 교정한다. 큰 로고/슬로건 및 대화 바깥 카드를 제거하고 헤더·말풍선·입력을 원본 기준으로 수정한다. 기존 바인딩, 전송/답장/반응/이미지/재생 경로를 보존한다.
2. 룸 관리 창의 모든 관리 폼을 한 화면에 펼치던 구성을 탭으로 분리하고 한국어로 정리한다. 사용자는 닉네임으로 사람을 검색하며 raw UID를 입력하지 않는다. 기존 룸/검색/초대 동작은 실제 서비스에 연결한다.
3. 정상 Release 빌드와 기존 실제 WinUI 동작 검사를 실행하고 DISPLAY3에서 변경 화면을 렌더링해 확인한다. 설정/거울/리뷰 전체 디자인 일치와 실제 Mac 실행 화면 비교는 후속 항목이며 이번 수정으로 전체 디자인 완료라고 말하지 않는다.

Mac 실행 화면을 이 Windows 환경에서 캡처하지 못했으므로 현재 단계는 원본 코드 기반 교정이다. 과거 테스트 이미지나 소스 분석을 실제 Mac 화면의 시각적 감사로 주장하지 않는다. 사용자 계정/기존 설치 앱을 강제 종료하거나 바꾸지 않고 합성 서비스 진단 빌드로 화면을 확인한다.

Commit: `fix(windows-ui): match Mac room and conversation structure`.

## 설정과 첫 실행 흐름 교정

- `SettingsScene.swift`의 560×400 설정 구조를 Windows의 560×440 client로 옮긴다. 일반/저장 설정은 제목·설명 왼쪽, 조작부 오른쪽의 16pt 그룹으로 구성한다. 단축키는 현재 조합이 보이는 행과 펼친 편집부로 구성하며 실제 등록 경로를 유지한다.
- `PairingView.swift`의 480×600 환영/권한/닉네임/연결 선택/생성/참여/완료 단계를 네이티브 Windows 첫 사용 흐름으로 연결한다. 기존 익명 세션의 profile/room 서비스를 사용하고 카메라·마이크가 없어도 메신저 설정을 계속한다. 기존 진단 목록은 상태 점검 창으로 구분한다.
- 입력 카드/글자 수/Enter 제출, 같은 이름 룸의 방장 닉네임, 생성 후 해당 룸의 초대 화면 진입을 원본에서 가져온다. 이미 열린 룸 관리 창의 오래된 목록도 새 룸을 다시 읽어 정확히 선택한다.
- 모델 실패·중복 제출·취소·다른 룸 선택 방어를 검증하고 DISPLAY3에서 실제 바인딩/렌더링을 확인한다. Mac 실기 스크린샷 및 실제 장치/기기 간 QA의 미완료 상태는 유지한다.

Commit: `feat(windows-ui): bring Mac settings and guided setup flow`.

## 룸 관리의 남은 데모 폼 제거

`RoomDetailView.swift`의 작은 제목·인원 헤더, 초대 링크/이름 변경/나가기 조작과 멤버 목록을 참고한다. 기존 생성·이름 변경 입력 폼을 상시 펼치지 않고 필요할 때만 Windows 네이티브 입력창으로 연다. 생성 실패는 입력을 보존하며, 생성 성공 후 목록 갱신만 실패한 경우 생성 성공을 보존하여 재생성으로 이어지지 않게 한다. 이름은 16 grapheme 기준으로 검증하고 서비스의 UTF-16 길이 제한이 유효한 이모지를 거부하지 않게 한다.

입력창이 열린 동안 룸 선택이 바뀌면 다른 룸에 이름 변경/나가기를 적용하지 않는다. 룸 순서는 해당 행의 컨텍스트 메뉴에서 변경하며 현재 선택과 다른 행에서도 명령 대상이 정확해야 한다. 기존 검색/초대 탭 서비스는 유지한다. 검색 결과에는 방장 닉네임을 표시한다. 이 변경은 메신저와 관리 창의 완전한 통합이나 Mac 검색 sheet/실기 이미지 parity의 완료를 뜻하지 않는다.

Commit: `fix(windows-ui): replace legacy room forms with contextual dialogs`.

검증: 정적 생성/이름 변경 폼이 보인다는 실제 WinUI 실패를 먼저 확인했다. Core의 이모지 길이/생성 후 갱신 실패 회귀 검사도 실패를 먼저 확인했다. 수정 후 Core272/App323, DISPLAY3 WinUI216개 통과. 멤버 이름은 렌더 완료를 기다린 뒤 검사하며 생성/이름 변경 입력창, 실패 시 입력 보존, 룸 전환 중 잘못된 대상 작업 방지, 컨텍스트 메뉴 대상 행 이동을 실제 바인딩과 조작으로 확인했다. Windows 버전은 0.4.4.0으로 구분한다.

## 대화창 안에서 룸과 연결 관리

Mac `RoomManagerWindow.swift`, `RoomDetailView.swift`, `RoomSearchView.swift`처럼 대화창의 +는 룸 생성, 검색 조작은 룸/사람 검색 화면을 연다. 룸 헤더에는 멤버·초대 링크·이름 변경·나가기를 배치한다. 기존 얼굴/화면 촬영 진입은 트레이/단축키 및 메신저의 작은 촬영 메뉴에 유지한다. 이전 별도 관리 창은 공통 메신저 동선에서 제외한다.

1. 기존 확인/입력창을 공용 룸 조작 컴포넌트로 옮겨 메신저와 기존 관리 창에서 사용한다. 선택 변경 시 다른 룸을 조작하지 않는 방어, 실패 입력 보존과 기존 서비스/RLS를 유지한다.
2. 순수 검색 모델로 룸/사람 동시 검색, 최신 검색 결과만 반영, 자기 계정 제외, 오류·취소를 처리한다. 네이티브 검색 화면은 300ms 자동 검색과 Enter 즉시 검색, 룸/사람 탭, 방장 닉네임, 이미 가입/연결한 대상 표시, 초대 링크 참여를 제공한다.
3. 메신저의 실제 룸/사용자 서비스에 연결하고 조작 완료 후 해당 룸 대화와 목록을 갱신한다. 닉네임/계정 변경과 창 종료에 이전 작업이 새 계정으로 넘어가지 않게 한다. 첫 사용 완료도 메신저의 해당 룸·초대 흐름으로 이어진다.
4. 순수 검색 모델을 실패부터 검증하고 DISPLAY3에서 메신저 헤더/멤버/검색/생성/참여/이름 변경/나가기·실패·룸 선택 변경 동작을 실제 WinUI로 확인한다. 정상 Release/서명 EXE를 생성하여 실제 설치본에 적용한다. Mac 실기 및 장치 QA는 별도 미완료 항목으로 유지한다.

Commit: `feat(windows-ui): manage rooms directly from the messenger`.
