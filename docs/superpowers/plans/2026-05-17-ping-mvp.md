# Ping MVP Supabase Implementation Plan

> 이 파일은 현재 코드베이스 기준의 실행 계획이다. 백엔드는 Supabase Anonymous Auth, Postgres RPC, RLS, 비공개 Storage bucket `ping-videos`를 사용한다. 서버 스키마와 정책의 단일 진실 출처는 `supabase/migrations/*.sql`이다.

## Goal

macOS 13 Ventura 이상 메뉴바 앱으로, Option+P → 3초 녹화 → Supabase 업로드 → 로컬 알림 → 3초 원형 재생까지 end-to-end로 안정화한다.

## Current Architecture

- SwiftUI + AppKit window control.
- `AppState` 중심 ObservableObject 상태 관리.
- `KeyboardShortcuts` 글로벌 단축키.
- `AVFoundation` 3초 MP4 녹화.
- Supabase Anonymous Auth session persistence in `SupabaseClient`.
- Supabase Postgres RPC for profiles, rooms, invitations, invite links, messages, cleanup.
- Supabase Storage private bucket `ping-videos` for MP4 objects.
- 10초 polling via RPC for rooms, invitations, incoming messages.
- Sparkle 2 appcast updates from `https://0minping.vercel.app/appcast.xml`.

## Required Invariants

- Keep `macOS: "13.0"` and `SWIFT_VERSION: "6.0"`.
- Do not call `.glassEffect()` directly outside `Ping/UI/Glass/GlassEffectCompat.swift`.
- Keep `.pingGlassEffect()` so macOS 26 Tahoe uses native `.glassEffect()` and macOS 13-25 uses the stable tint fallback.
- Do not replace `SMAppService.mainApp` with launch agent plist logic.
- Do not edit `Ping.xcodeproj` directly; update `project.yml` and run `xcodegen generate`.
- Do not commit `Resources/Supabase.plist`.
- Keep `observeIncoming` duplicate defenses: per-stream `yieldedIds` and app-wide `notifiedMessageIds`.
- Keep one shared `CameraManager` instance owned by `AppDelegate`.
- Keep `MirrorWindow(rootView: EmptyView())` followed by `contentView` replacement where the window self-reference is needed.

## Backend Contract

### Auth

- `SupabaseClient.bootstrap()` creates or restores an anonymous session.
- Sessions persist in sandboxed Application Support as `SupabaseSession.json`. The app runtime does not use Keychain for Supabase session load/save/clear.
- Refresh failure surfaces `PingError.supabaseSessionExpired` instead of silently creating a new identity.

### RPCs

Core RPCs used by the app:

- `ping_upsert_profile`
- `ping_get_profile`
- `ping_search_profiles`
- `ping_create_room`
- `ping_my_rooms`
- `ping_search_open_rooms`
- `ping_join_room`
- `ping_leave_room`
- `ping_rename_room`
- `ping_invite_user`
- `ping_send_invitation`
- `ping_incoming_invitations`
- `ping_accept_invitation`
- `ping_reject_invitation`
- `ping_create_invite_link`
- `ping_accept_invite_link`
- `ping_create_message`
- `ping_incoming_messages`
- `ping_get_message`
- `ping_mark_message_seen`
- `ping_update_last_used_room`
- `ping_cleanup_expired_data`

When changing SQL argument names, update Swift call bodies at the same time. PostgREST named args make mismatches runtime failures.

### Storage

- Bucket: `ping-videos`
- Object path: `<senderUid>/<videoId>.mp4`
- Upload content type: `video/mp4`
- Upload header: `x-upsert: true`
- Sender owns the object prefix.
- Receiver read access depends on a non-expired uploaded message row.

## Implementation Tasks

### 1. Session And Config

- Verify missing `Resources/Supabase.plist` fails with a useful message.
- Verify anonymous session survives app relaunch.
- Verify expired or deleted server session does not silently create a new profile.

### 2. Room And Invitation Flows

- Create room from onboarding.
- Search open rooms and profiles with prefix normalization.
- Join room with room/user limits enforced.
- Invite user and reuse pending room where applicable.
- Accept/reject invitation and update both room lists on next poll.
- Create and accept invite links.
- Rename room as a member.

### 3. Recording And Upload

- Use the single `CameraManager` instance.
- Record exactly 3 seconds.
- Save local sent copy if enabled.
- Upload MP4 to `ping-videos`.
- Create receiver messages through `ping_create_message`.
- Update last used room for single-room send.
- On success, close mirror without toast.
- On failure, keep mirror in failed state with Enter retry.

### 4. Incoming Messages

- Poll `ping_incoming_messages()` every 10 seconds.
- Suppress duplicate notifications.
- Show local notification with message id.
- On click, fetch message metadata, download Storage object, play for 3 seconds, mark seen.
- Ensure older catch-up messages do not spam repeated notifications.

### 5. Cleanup

- Call `ping_cleanup_expired_data()` best-effort on startup.
- Do not depend on server scheduled jobs.
- Validate expired messages, invitations, invite links, and unreferenced Storage objects are cleaned by the RPC.

### 6. Release

- Run tests.
- Run release script.
- Confirm `dist/Ping-v<MARKETING_VERSION>.dmg`.
- Confirm copied download artifact under `web/public/downloads/`.
- Confirm appcast regenerated and signed by Sparkle tooling.

## Common Failure Triage

### Supabase 400 During Send

Check the response body first. The app surfaces `Supabase 요청이 실패했습니다. (400) <message>`.

Likely sources:

- Storage upload rejected: bucket missing, MIME mismatch, file over limit, or path prefix not equal to current uid.
- `ping_create_message` rejected: invalid room membership, self-send, empty nickname/video id/url, or `x_ratio`/`y_ratio` outside `0...1`.
- RPC argument mismatch after SQL changes.
- Anonymous sign-ins disabled or stale local session.

Useful checks:

```bash
log show --style compact --last 1h --predicate 'process == "Ping"' | rg "Supabase|400|ping_create_message|storage|upload|failed" -C 2
rg -n "ping_create_message|uploadObject|x_ratio|y_ratio" Ping supabase/migrations
```
